# Himalayan Runners — App Structure Brief

A beginner-friendly guide to every file and folder in this project, plus a list of files you can safely delete.

---

## What Is This App?

**Himalayan Runners** is a trek-booking website built with:

| Technology | Purpose |
|---|---|
| **Next.js 16** (React 19) | The web framework — handles pages, routing, and server-side logic |
| **Supabase** | Backend-as-a-service — provides the database (PostgreSQL), user authentication, and file storage |
| **Razorpay** | Payment gateway — lets users pay for trek bookings |
| **Tailwind CSS 4** | Utility-first CSS framework for styling |
| **TypeScript** | JavaScript with type safety |

The app has **three user roles**:
1. **User** — browses treks, books & pays
2. **Guide** — manages their own treks and itineraries
3. **Admin** — full control: manage treks, bookings, coupons, and guides

## Root-Level Files

| File | What It Does |
|---|---|
| `package.json` | Lists all dependencies (libraries) and scripts (`npm run dev`, `npm run build`, etc.) |
| `package-lock.json` | Auto-generated lock file that pins exact dependency versions |
| `tsconfig.json` | TypeScript configuration — tells the compiler how to process `.ts`/`.tsx` files |
| `tsconfig.tsbuildinfo` | Auto-generated cache file used by TypeScript for faster builds |
| `next.config.ts` | Next.js configuration (currently empty/default) |
| `next-env.d.ts` | Auto-generated by Next.js — adds TypeScript types for Next.js |
| `middleware.ts` | Runs on every request before the page loads. Refreshes Supabase auth cookies so users stay logged in |
| `global.d.ts` | TypeScript type definitions for Razorpay (tells TS what `window.Razorpay` looks like) |
| `globals.css` (inside `app/`) | The main CSS file — imports Tailwind CSS |
| `eslint.config.mjs` | ESLint configuration — sets up code-quality rules |
| `postcss.config.mjs` | PostCSS configuration — tells it to use Tailwind CSS |
| `.env.local` | **Secret environment variables** (Supabase keys, Razorpay keys, site URL). Never committed to git |
| `.gitignore` | Tells git which files to ignore (node_modules, .env.local, .next, etc.) |

## Folder Structure

### `app/` — All Pages and API Routes

Next.js uses **file-based routing**: each folder with a `page.tsx` becomes a URL.

#### Main Pages

| Path | URL | What It Does |
|---|---|---|
| `app/page.tsx` | `/` | **Home page** — shows the navbar, hero banner, category filters, and trek cards |
| `app/layout.tsx` | (wraps all pages) | **Root layout** — sets the HTML shell, metadata (title), and loads global CSS |

#### Auth Pages (`app/auth/`)

| Path | URL | What It Does |
|---|---|---|
| `app/auth/layout.tsx` | (wraps auth pages) | Layout wrapper for all auth pages |
| `app/auth/login/page.tsx` | `/auth/login` | Login page with email/password + Google sign-in |
| `app/auth/register/page.tsx` | `/auth/register` | Registration page — creates a new user account |
| `app/auth/callback/route.ts` | `/auth/callback` | **API route** — handles the redirect after Google/email login (exchanges auth code for session) |
| `app/auth/forgot-password/page.tsx` | `/auth/forgot-password` | Sends a password reset email |
| `app/auth/reset-password/page.tsx` | `/auth/reset-password` | Page where user sets a new password (after clicking reset link) |
| `app/auth/verify-email/page.tsx` | `/auth/verify-email` | Shows a "check your email" message after registration |

#### Trek Pages (`app/treks/`)

| Path | URL | What It Does |
|---|---|---|
| `app/treks/page.tsx` | `/treks` | **Explore Treks** page — lists all treks with filters |
| `app/treks/[id]/page.tsx` | `/treks/<trek-id>` | **Trek detail** page — shows description, itinerary, pricing, coupon field, and Pay button |

#### Admin Pages (`app/admin/`)

| Path | URL | What It Does |
|---|---|---|
| `app/admin/layout.tsx` | (wraps admin pages) | **Admin guard** — checks if the user is logged in AND has role `admin`. Redirects to `/` if not |
| `app/admin/page.tsx` | `/admin` | Redirects to `/admin/dashboard` |
| `app/admin/dashboard/page.tsx` | `/admin/dashboard` | **Admin dashboard** — shows stats (total treks, bookings, guides, users) and quick-action cards |
| `app/admin/dashboard/debug.tsx` | (not a route) | Debug component that displays the current user's profile data. Used during development |
| `app/admin/treks/page.tsx` | `/admin/treks` | List and manage all treks |
| `app/admin/treks/new/page.tsx` | `/admin/treks/new` | Create a new trek form |
| `app/admin/treks/[id]/page.tsx` | `/admin/treks/<id>` | Edit an existing trek |
| `app/admin/bookings/page.tsx` | `/admin/bookings` | View all bookings |
| `app/admin/coupons/page.tsx` | `/admin/coupons` | Create and manage discount coupons |
| `app/admin/guides/page.tsx` | `/admin/guides` | Manage guide users |

#### Guide Pages (`app/guide/`)

| Path | URL | What It Does |
|---|---|---|
| `app/guide/layout.tsx` | (wraps guide pages) | Guard layout — checks if user has guide role |
| `app/guide/login/page.tsx` | `/guide/login` | Guide-specific login page |
| `app/guide/dashboard/page.tsx` | `/guide/dashboard` | Guide dashboard — shows their assigned treks |
| `app/guide/trek/[trekId]/manage/page.tsx` | `/guide/trek/<id>/manage` | Manage a specific trek's itinerary |

#### Payment & Checkout

| Path | URL | What It Does |
|---|---|---|
| `app/checkout/page.tsx` | `/checkout` | **Unused placeholder** — a basic static checkout page (payment is actually handled inline on the trek detail page) |
| `app/success/page.tsx` | `/success` | Payment success page — shown after a successful Razorpay payment |
| `app/success/success-content.tsx` | (component) | The actual content of the success page (separated to handle client-side logic) |

#### Legacy Redirect Pages

| Path | URL | What It Does |
|---|---|---|
| `app/login/page.tsx` | `/login` | Just redirects to `/auth/login` |
| `app/register/page.tsx` | `/register` | Just redirects to `/auth/register` |

#### API Routes (`app/api/`)

These are backend endpoints that run on the server.

| Path | URL | What It Does |
|---|---|---|
| `app/api/payment/create-order/route.ts` | `POST /api/payment/create-order` | Creates a Razorpay order and returns order details to the frontend |
| `app/api/payment/verify/route.ts` | `POST /api/payment/verify` | Verifies Razorpay payment signature and saves the booking to the database |
| `app/api/coupon/validate/route.ts` | `POST /api/coupon/validate` | Validates a coupon code and returns the discount amount |
| `app/api/coupon/generate/route.ts` | `POST /api/coupon/generate` | Generates coupon codes (admin use) |
| `app/api/debug/env/route.ts` | `GET /api/debug/env` | **Debug only** — checks if Razorpay env vars are set (should be removed in production) |
| `app/api/auth/change-role/` | (empty folder) | Empty folder — does nothing |

### `utils/` — Utility/Helper Files

#### `utils/supabase/`

| File | What It Does |
|---|---|
| `client.ts` | Creates the **browser-side** Supabase client (used in client components with `"use client"`) |
| `server.ts` | Creates the **server-side** Supabase client (used in server components and API routes). Also exports `createServiceRoleClient` for admin-level access that bypasses RLS |
| `midleware.ts` | **Unused** — A Supabase middleware helper. The actual middleware logic is in the root `middleware.ts` file. (Also note the typo in the filename: "midleware" instead of "middleware") |
| `storage.ts` | Handles uploading and deleting trek images to/from Supabase Storage |

#### `utils/auth/`

| File | What It Does |
|---|---|
| `actions.ts` | Server actions for authentication: sign up, sign in with Google, complete user profile |
| `helpers.ts` | Validation functions for email, password, and error message formatting |

#### `utils/razorpay/`

| File | What It Does |
|---|---|
| `client.ts` | **Unused** — Helper functions to create Razorpay orders and redirect to hosted checkout. Not imported anywhere (the `CheckoutButton` component calls the API directly instead) |

## Files You Can Safely Delete

These files are **not used** by the app and can be removed:

### Unused Code Files

| File | Reason |
|---|---|
| `components/RazorpayPaymentButton.tsx` | Older payment button — replaced by `CheckoutButton.tsx`. Not imported anywhere |
| `utils/supabase/midleware.ts` | Unused middleware helper with a typo in the name. The root `middleware.ts` handles this |
| `utils/razorpay/client.ts` | Unused helper — `CheckoutButton` calls the API directly. Not imported anywhere |
| `app/checkout/page.tsx` | Static placeholder page — never used. Payment happens inline on the trek detail page |
| `app/api/debug/env/route.ts` | Debug endpoint that exposes env var status. Should not exist in production |
| `app/api/auth/change-role/` | Empty folder with no files |
| `app/admin/dashboard/debug.tsx` | Debug component for development — not needed in production |

### Unused Public Assets

| File | Reason |
|---|---|
| `public/file.svg` | Default Next.js template file — not referenced anywhere |
| `public/globe.svg` | Default Next.js template file — not referenced anywhere |
| `public/window.svg` | Default Next.js template file — not referenced anywhere |

| File | Reason |
